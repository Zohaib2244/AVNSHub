# Changelog

All notable changes to AVN Hub are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **Maintaining this file:** add an `## [Unreleased]` entry as you work, grouped
> under **Added / Changed / Fixed / Removed**. On release, rename `Unreleased` to
> the new version with a date, bump `version` in `package.json` and the
> `BootSequence` header string, and start a fresh `Unreleased` block.

## [Unreleased]

### Added
- **Minimum sizes for Slot Layout resizing.** Manifests (built-in and custom `manifest.json`) accept `minPx: { width, height }`, the smallest cell box a widget still works in; drag-resize converts it to a span floor at the current cell pitch and stops there. A widget without an `S` layout gets a 300x150 floor automatically (and one without `M` either gets 400x250), so it can't be dragged into a box it has no layout for. The floor never exceeds the current footprint, so a widget already below it can't "shrink" into a larger rect over its neighbours. See `minPixelSize` in [`lib/grid/sizeClass.ts`](lib/grid/sizeClass.ts).
- **CLI-style prompt recall in NutBot chat.** Up/Down in the chat input walk back through previously sent prompts and drop them into the box ready to edit or re-send ([`NutBotChat.tsx`](components/widgets/default/nutbot/chat/NutBotChat.tsx)), the way a shell's history does. Stepping back down past the newest entry restores the draft you were typing before the first Up; consecutive duplicate sends collapse into one entry; history holds the last 100 prompts, persists in `sessionStorage`, and is deliberately *not* cleared by "new chat" — a shell keeps its history across commands. Because the input is a multi-line textarea, recall only fires when the caret is on the line the key would otherwise leave (first line for Up, last for Down) with a collapsed selection, so Up/Down still navigate normally inside a multi-line draft. Editing a recalled prompt exits recall and re-stashes the edit, so no typed text is ever lost to a stray Down.
- **Skip → build from inside Ideate.** Ideate now has a `skip → build` control in its handoff strip, available the whole time you're in the stage rather than only at the entry picker — for changing your mind after committing to Ideate. When a run produces no mockups the empty state stops being a dead end too: it explains that Build works fine without a mockup and offers the same control inline. Skipping carries the Plan brief into Build exactly as finalizing does, but attaches no design reference, leaves `hasIdeateRounds` alone (the project shouldn't claim rounds it never produced), and keeps any reference from an earlier finalize instead of silently discarding it.
- **Boot sequence overhaul.** The first-load boot log ([`BootSequence.tsx`](components/dashboard/BootSequence.tsx)) now boots NutBot's actual face (`NutBotFaceV2`, driven through `thinking` → `excited` via a new `boot_complete` signal in `lib/nutbotSignal.ts`) instead of showing plain text alone; two of its status lines report real data from `/api/homelab` and `/api/system-stats` (falling back to canned copy if unconfigured/slow); a rotating flavor line varies the script per load; click or any keypress skips straight to the dashboard; a synthesized power-on chime (raw Web Audio oscillators, no bundled asset) can play on completion, off by default via a new `bootChime` pref (toggle in Hub Core → General); and the flat opacity fade-out was replaced with a two-panel chunky-block wipe that splits along an accent-orange seam.
- **Per-widget SPEC.md.** After every successful build turn the Widget Creator writes a `SPEC.md` into the widget's own folder ([`lib/widget-creator/projectSpec.ts`](lib/widget-creator/projectSpec.ts)) capturing its intent, per-size content, data shape, and pipeline origin; edit-mode prompts read it back as authoritative context so the harness (or a fresh session on another device) never has to re-derive what the widget is for.
- **Name/icon/slug at project creation.** The Widget Creator's "new widget" step now has an identity form (with auto-derived slug and a "decide later" toggle); decided values seed Build mode's settings and survive Plan-mode handoffs that don't supply their own icon.
- **Pipeline handoff indicators.** Ideate and Build now show a "carried over from plan" chip (with the brief's title) when a brief exists, and Build shows a "mockup reference attached" chip that expands into a live preview of the finalized Ideate mockup — what each stage feeds the next is visible instead of implicit.
- **Canvas-widget worked example in the `avn-widget-build` skill** (and `docs/CREATING_WIDGETS.md`): a complete strict-null-safe refs + ResizeObserver + DPR + RAF pattern, so canvas/animation widgets no longer send the harness exploring other widgets' source for conventions.
- **Widget Creator server-side generation mutex.** "One generation at a time" is now enforced on the server ([`lib/widget-creator/generationLock.ts`](lib/widget-creator/generationLock.ts)) instead of only in one browser tab's memory — a second tab or device starting a build/ideate run while one is in flight gets a clear "already running" error instead of two harnesses racing on `customComponentMap.tsx`, the registry JSON, and each other's tsc checks. Lock lives on `globalThis` (survives dev-server HMR), stale takeover after 30 min, always released on completion or client abort.
- **Post-run write audit.** After every build turn the generate route diffs `git status --porcelain` from before the run ([`lib/widget-creator/gitAudit.ts`](lib/widget-creator/gitAudit.ts)); the harness runs with `bypassPermissions`, so any file it touched outside the widget's own folders (`components/widgets/custom/<slug>/`, `app/api/<slug>/`, the registry files) now surfaces as a warning card in the build chat instead of silently landing in the working tree. Skipped gracefully when git is unavailable.
- **Generated API routes are now tracked and cleaned up.** Registration records from disk whether a widget shipped its own `app/api/<slug>` route (`flags.hasApiRoute` — never trusted from the LLM-authored manifest); deleting the widget now removes that route too instead of orphaning it forever. Creating a widget whose slug collides with an existing `app/api` route (e.g. `uptime`) is rejected up front so a generated route can never overwrite a core one.
- **Widget Creator projects now sync through the shared KV store.** Project list state, per-project transcripts/ideate rounds, Plan/Ideate/Build session ids, and pending install records now use the same localStorage-first/server-reconciled pattern as hub prefs, so creator work survives browser/device switches instead of living only in one tab.
- **Plan mode's live brief panel.** The finalized/in-progress plan now lives in the Plan stage's left sidebar ([`PlanBriefPanel.tsx`](components/widgets/default/nutbot/creator/PlanBriefPanel.tsx)) instead of inline in the chat transcript — it only updates when the model actually returns a revised `widget-brief` block, so asking an unrelated question in chat no longer disables its build/continue-to-ideate/edit buttons (they now disable only while a generation is actually running). Includes an S/M/L size toggle. Chat shows a short "plan updated — see the panel" note instead of a duplicate interactive card.
- **Sibling-widget read detection.** The build/edit harness (any of claude/codex/opencode) is now watched for Read/Glob/Grep calls that target a *different* widget's folder under `components/widgets/custom/`; a "[read audit]" card surfaces in the build chat when it happens, on top of the existing write-audit. `claude` specifically also gets its Read/Glob/Grep tools scoped to its own target folder via `--allowedTools`/`--disallowedTools`.
- **Same-harness retry on a stale `--resume` session.** If continuing an old claude session fails outright (e.g. its session store expired after picking an edit back up weeks later), the chain now retries that harness once fresh with the full prompt before falling through to a different harness.
- **Image attachments in Build/Edit chat.** A paperclip button on the build chat input attaches screenshots/design references (up to 4, with thumbnail previews); the server writes them to temp files and points the harness at them with an explicit "view these with the Read tool before writing code" section — which also makes the per-size visual references from the settings pane actually work (previously they produced an "[image attached]" line with no image behind it). Temp files are cleaned up after every run.
- **Ideate mockups are now pinned to real widget footprints.** The mockup prompt specifies fixed block dimensions per size (S 220×140 … L 680×300) with hard fit rules — no overflow, internal-list-only scrolling, density over decoration, smaller sizes show fewer things — so a finalized design can no longer be a sprawling page that never had a chance of fitting the canvas.
- **"Space discipline" section in the `avn-widget-build` skill** (via `lib/widget-creator/prompts/widget-build-spec.md`, skills re-synced): the same footprint budget and fitting rules for real builds — `height: 100%` roots, `overflow-y: auto` only on inner lists with `min-height: 0` parents, truncation over wrapping, compact paddings.

### Changed
- **Widget Creator builds in a private workbench, never in the live tree.** Each widget being created, edited or imported gets a source mirror outside the repo ([`lib/widget-creator/workbench.ts`](lib/widget-creator/workbench.ts), design in [`docs/WIDGET_WORKBENCH.md`](docs/WIDGET_WORKBENCH.md)): ~5 MB of source with `node_modules` and the Prisma client symlinked, other widgets' folders left out. The harness runs there; its changes are diffed by content hash, anything outside the widget's own folders is reverted and reported, and `tsc` gates only the widget's own diagnostics. A passing draft is applied to the live tree file-by-file via temp file + rename, after checking live didn't change underneath it (per-file three-way with the last agreed base), with the component map repointed before old files are deleted. A failing draft stays in the workbench for the next fix turn while the live widget keeps working, and the widget being edited stays on the canvas throughout. Replaces the `.tsx.bak` backups, the `componentKeepAlive` inotify race, and hiding widgets during edits.
- **Widget import goes through the same workbench.** An archive is unpacked into the widget's workbench, rejected if it references uninstalled npm packages, contains unsafe paths or doesn't type-check (nothing installed), and otherwise applied and registered; importing an id you already have now updates it in place. Export adds the widget's `app/api/<id>/` route (as `api/`) and `$meta.hubVersion`, and the importer reports version skew.
- **Widget settings open as a centred dialog with save.** The gear no longer drops a small panel beside the card: [`WidgetSettingsPopover`](components/framework/WidgetSettingsPopover.tsx) is now an Android-widget-style dialog in the middle of the screen, with every other widget dimmed and the card being configured left lit in a cut-out (a fixed box whose spread `box-shadow` is the dim, so no stacking-context gymnastics). Changes are a draft: the save button stays inert ("no changes") until a value really differs from what's stored — changing something back clears it — and saving applies only the changed keys, then closes. The ×, a click anywhere outside the panel, or Escape close and discard. "remove widget" still acts immediately. Long settings lists scroll inside the dialog while the header and save row stay put.
- **Slot Layout widget names no longer take space from content.** The in-flow `stamp`/`crest` header cost ~25-46px of height in every card, a large share of a one-row cell. Inside a slot cell `WidgetShell` now renders the name + icon as a small `.block-hover-tag` sitting on the card's top-left border instead: hidden at rest, faded in on hover and always shown in edit mode (shifted clear of the move button), with `pointer-events: none` so it never blocks the content under it. `ghost` still hides it entirely; `stamp` and `crest` both show the tag. Graph Layout, whose rows grow with content, keeps the in-flow header.
- **Widget build spec teaches the new sizing model.** `widget-build-spec.md` (synced to both harness skills) and `docs/CREATING_WIDGETS.md` now describe the pixel-based S/M/L thresholds, and add rules targeting the crops seen in practice: rows must shrink (`minWidth: 0` on text/inputs, `flex: 0 0 auto` on buttons), free text uses an auto-growing capped `textarea`, no duplicate primary actions, no widget title repeated inside the content, secondary sections become tabs instead of collapsibles under a list, and `minPx` for widgets that genuinely break when small.
- **Slot Layout picks S/M/L from the cell's real pixel size, not its span count.** A "1x1" is a different box in the left grid, the base grid and Central Base, and changes again with screen size and frame-ratio drags, so the old area rule (1 cell -> S, 2-3 -> M, 4+ -> L) routinely handed widgets a layout built for a different amount of room — the main cause of cropped content. [`SlotRegion`](components/framework/SlotRegion.tsx) now keeps a `ResizeObserver` on its own box (unaffected by hover-expand, which positions cells absolutely inside it) and [`sizeClassForFootprint`](lib/grid/sizeClass.ts) classifies the resulting pixel box: **S** when either side is cramped (<300px wide or <150px tall — so 1x1, 1x2, 2x1 and one-row strips like 3x1), **L** at >=600x250 or >=400x400, **M** in between (2x2). Orientation likewise follows the pixel aspect ratio. Until the first measurement the span fallback is 1x1/1x2/2x1 -> S, 2x2 -> M, larger -> L. The fills-its-whole-region rule is unchanged. Iframe widgets now also receive `orientation` in `NUTMAG_CONTEXT`.
- **Form controls and widget roots can no longer push past a card's right edge.** Cards clip horizontally, and an `<input>`'s browser-default intrinsic width (plus flex items' `min-width: auto`) was enough to shove a text box's edge or its neighbouring button out of a narrow cell. `globals.css` now lets inputs/textareas/selects shrink (`min-width: 0; max-width: 100%`) and caps a card's direct children at the card width, framework-wide.
- **Canvas-wide default for widget name & icon.** Hub Core > Appearance gains a `widget name & icon` dial (ghost / stamp / crest) directly under `widget backdrop`, backed by a new [`lib/headerStyle.ts`](lib/headerStyle.ts) store that mirrors `lib/theme.ts` (canvas-scoped key, listener set, server reconciliation, `subscribeCanvases()` re-sync). It is the same two-tier arrangement the widget backdrop uses: the per-widget `name & icon` control now defaults to **auto**, meaning "follow the canvas dial", and any other value is an explicit per-widget override. Legacy `showHeader: true` migrates to `auto` rather than `stamp` — the look is identical since the global default *is* stamp, but existing widgets now track the dial instead of being pinned to it. Unlike the backdrop this can't be a CSS cascade (it selects markup, not paint), so `WidgetShell` subscribes to the store; server-rendered widgets therefore show `stamp` until hydration reads localStorage, the same way the widget arrangement already resolves client-side.
- **NutBot's buttons now read as buttons.** Almost every control across the terminal, chat and Widget Creator (send, skip → build, back, reset, add, attach, size tabs, brief actions, the ideate card actions, the Models trigger and dialog buttons, …) was `background: transparent`, so at these sizes a 1px border was the only thing separating a button from the prose around it. They now sit on a real surface via a new `--nb-btn-bg` on `.nutbot-terminal`. It is not `--bg-nested` — that token is *darker* than `--bg-card` in every dark palette, so filling a button with it read as a recess; the new one is mixed from the nested background toward `--text-primary`, which lifts in dark palettes and deepens in light ones and stays distinct from both `--bg-card` and `--bg-nested` in each (verified 1.23–1.44:1 against both, across all eight palettes × both modes). Derived with `color-mix` like the neighbouring `--nb-muted`, so no palette needed new tokens. Accent-fill hovers are unchanged and now transition from a surface rather than from nothing; the ideate stepper's hover fill was flipped to `--nb-btn-bg-hover` (it was `--bg-nested`, which now made hover *recede*), and the disabled brief button swapped `transparent` for `--bg-nested` so it reads as inert instead of as a hole between filled siblings. Segmented-control internals (`.term-tab`) and dropdown rows (`.hp-item-button`, `.nm-opt`) deliberately stay transparent — they sit on their own track/menu surface, which already frames them.
- **Widget Creator entry cards reveal their description on hover.** The Plan / Ideate / Build cards in the "new widget" step now rest as just an enlarged icon + name, centred; hovering (or keyboard-focusing) one shrinks the name back to label size and grows the description in below it, pushing the name up. The reveal uses a `grid-template-rows: 0fr → 1fr` transition rather than a fixed pixel height, so it works for any description length. On touch/coarse pointers and under `prefers-reduced-motion` the cards render in their expanded state with no transitions, since there is no hover to trigger them.
- **Widget name & icon is now a three-way choice instead of an on/off toggle.** Every widget's settings popover has a `name & icon` segmented control ([`FRAMEWORK_SETTINGS`](config/widgets.tsx)) with three modes: **ghost** (no header at all), **stamp** (the small uppercase DotGothic label bar every widget has used until now — still the default), and **crest** (the namecard's boxed identity mark + large title, borrowed from the Identity widget and scaled to fit a normal card). Rendered by [`WidgetShell`](components/framework/WidgetShell.tsx); `.block-crest` in `globals.css` mirrors `.namecard-mark`/`.namecard-logo`, drops its initials and shrinks under 190px, and hides entirely at S like `.block-label` already did. The boolean `showHeader` is migrated on read (`false` → `ghost`, `true` → `stamp`) inside `resolveSettings` — the single funnel both layout stores and the settings popover share — so existing headerless widgets stay headerless instead of silently falling back to the default.
- **New `segment` settings-field type.** A string field with 2-4 fixed options rendered as an inline `.seg-row`/`.seg-btn` segmented control rather than a dropdown; validated exactly like `select`. The `name & icon` control is the first user. `select` remains the right choice for longer option lists.
- The `name & icon` control is omitted for `customHeader` widgets (spotify, github, nutbot), which draw their own header and never render the shell's — previously they showed a `show name & icon` toggle that did nothing.
- **Deleting a custom widget now fully removes its creator project** (chat/brief/ideate history included) instead of resetting it back to "In Progress" — the previous behavior preserved history on purpose, but a deleted widget leaving a stale entry in either list was more confusing than useful.
- **Edit-turn prompts no longer resend stale per-size descriptions/notes from the original Plan/Ideate brief as "the spec"**, and the harness now maintains `SPEC.md` itself on edit turns (instead of the server re-deriving it from client-side settings that never track chat-only edits) — fixes edits being silently re-fulfilled/reverted (e.g. a deleted element reappearing because the original brief still mentioned it).

### Fixed
- **Claude couldn't write its own widget files.** The creator's per-run tool scope denied `Read` on all of `components/widgets/custom/**` and allowed only the run's own folder, but deny beats allow and claude treats a Read deny as blocking writes. Siblings are now denied by name (and aren't mirrored into workbenches at all).
- **Every claude generation reported "All harnesses hit a limit (quota)".** Claude Code 2.1.x emits a `rate_limit_event` status frame (normally `allowed`) on every run, which matched the quota pattern; only a `rejected` status is treated as a limit now.
- **Edits to `globals.css` stopped reaching the browser.** The file started with `@import "tailwindcss"`, so all ~2,800 lines of hand-written CSS were compiled through `@tailwindcss/postcss`, whose per-file compiler cache in Turbopack's long-running dev worker kept returning the previous output (reproduced outside Next: the same plugin instance given edited text for the same path emits the old CSS). Changes stayed invisible across restarts until `.next/dev` was deleted. Tailwind's at-rules (`@import "tailwindcss"`, `@theme inline`) now live in a new [`styles/tailwind.css`](styles/tailwind.css), imported first by both `app/layout.tsx` and the wallpaper build, and `globals.css` is plain CSS that skips the plugin. Verified live: in-place and replace-style writes both reach an open page and a fresh load.
- **Spotify no longer logs an error on every poll when it isn't set up.** Missing credentials throw a typed `SpotifyNotConfiguredError`; `/api/now-playing` answers `{ notConfigured: true }` and `/api/spotify-control` a 400, without logging, and the Now Playing / Spotify Visualizer widgets say "not configured — add credentials in settings" instead of "spotify idle".
- **The boot log no longer reports fake results.** The hard-coded `init display drivers OK`, `mount /dev/homelab OK` and `spotify.auth.handshake OK` lines are gone; every status line is now a real check made during the animation (system telemetry, storage, homelab status source, Spotify credentials), shows `FAIL`/`WARN`/`SKIP` when that's the truth, and the version comes from `package.json`. `storage.mounts` warns on data mounts ≥95% full and on fstab mounts that aren't mounted — `/api/system-stats` now returns `missing_mounts` (fstab `/mnt`/`/media` entries absent from `/proc/self/mounts`), which is how a USB drive that dropped off the bus shows up.
- **Spotify Visualizer's elapsed time and progress bar froze between polls.** They were read from refs during render, so they only moved when a poll re-rendered the widget; the animation loop now writes them straight to the DOM each frame.
- **Lint: 36 errors → 0.** Real bugs among them: Weather read the clock and a ref during render for its stale indicator (now tied to the payload that was stale), Weather/Quick Links built icon components during render, several "latest value" refs were written during render (Pomodoro, NutBot face, Shells), and effects that only existed to reset state (placement popover highlight, World Clock ringing toggle, Publishing Email Builder selection, Pomodoro reset, Quick Links zen mode) now update in the event handler or during render. One-time localStorage loads keep their effect with a documented disable; CommonJS scripts may `require()`.
- **Boot log no longer has a line through it.** The wipe's two half-screen panels meet at the vertical centre with an accent-orange border on each, and the log block is centred on the same line, so the seam ran straight through the text for the whole boot. The seam is now transparent while booting and only lights up as the panels split apart on exit ([`BootSequence.tsx`](components/dashboard/BootSequence.tsx)).
- **Weather settings dialog was trapped and cropped inside its card.** The slot card's `contain: layout paint` makes `position: fixed` resolve against the card, so the "full-screen" overlay rendered inside the widget and its 320px panel was cut off in any small cell. It is now portaled to `<body>`, capped to the viewport, and rendered via a plain function rather than a component declared inside render, which had been remounting the form (and dropping input focus) on every keystroke.
- **NutBot tab transitions no longer jump.** Switching between log / chat / shells / creator ([`NutBotTerminal.tsx`](components/widgets/default/nutbot/NutBotTerminal.tsx)) was a crossfade that briefly showed two panels at once — but `.term-tab-panel` sits in normal flow, so for ~150ms both panels stacked and the body's height doubled. Worse, the body restyles per tab (block vs flex, `7px 9px` / `8px` / `0` padding, `overflow: auto` vs `hidden`) and those classes flipped at the *start* of the transition, re-laying-out the outgoing panel under the incoming tab's rules. Switches now run fade-out → swap → fade-in, so exactly one panel is ever in flow and the container restyle happens while everything is at `opacity: 0`. `display` is a plain inline style again instead of being driven through framer's `transitionEnd`, which raced on fast switching; `.term-tab-panel` also gained the `display: flex` it was missing while already setting `flex-direction: column`. Adds directional easing, `prefers-reduced-motion` support (via `useReducedMotion`), a cancel path when you click back to the panel that's still on screen, and a 400ms failsafe so a switch interrupted by a resize or canvas change can't leave the body blank. Restoring the stored tab on load is now instant rather than fading in from `log`, and the scroll-to-bottom effect is limited to the log feed — it was yanking chat, creator and shells to the bottom on every switch.
- **A harness deleting a component file can no longer 500 the dashboard.** codex's `apply_patch` rewrites files as `*** Delete File` followed by `*** Add File`; the dev server recompiles inside that gap, `customComponentMap.tsx`'s static import fails to resolve, and every page dies — then the crash disconnects the browser, cancelling the SSE stream, which aborts the run mid-patch so the replacement never lands and the widget is left half-written. The route already wrote `.tsx.bak` backups but only consulted them *after* the run, long past the damage. [`componentKeepAlive.ts`](lib/widget-creator/componentKeepAlive.ts) now watches the widget's folder for the whole run and restores a `.tsx` from its backup the moment it disappears, reporting it into the build chat; the harness's own write lands afterwards and still wins. Verified against a simulated delete-then-add: file survives the window with content intact, the later write is not fought, and the watcher stops cleanly so post-run cleanup and real deletes still work. This narrows the exposure to a single inotify hop rather than closing it — both this and Turbopack watch the same events with no ordering guarantee; running the harness in a worktree and syncing atomically remains the fix that would eliminate the class.
- **Editing a prompt no longer silently fails to reach the harness.** `checkSkillOrError()` only ever asked whether a skill *file* existed, never whether it matched the prompt it is generated from — so editing `lib/widget-creator/prompts/*.md` and not running `npm run sync:widget-skill` left every harness running the older copy with no warning anywhere. A new rule added to the build spec simply had no effect. It now also compares mtimes (`isSkillStale()`) and refuses the run with an actionable message naming the source file and the sync command. Found the hard way: the "never delete the component file" rule added to fix a site-killing crash sat un-synced while the delete kept happening.
- **A custom widget can no longer take the whole dashboard down.** `config/customComponentMap.tsx` holds one *static* `import()` per custom widget, so an entry whose `.tsx` is missing isn't a broken widget — it's a module-resolution failure that cascades through `customWidgets.ts` → `lib/layout.ts` → `LayoutProvider` → `app/page.tsx` and 500s the entire page. `WidgetShell`'s error boundary can't catch it, because the failure happens at module build, not render. Three fixes: `addToComponentMap()` no longer falls back to a *guessed* conventional path when the component file can't be found — it refuses to write the entry (the import route called it exactly that way, `findComponentModule(id) ?? undefined`, so an import of a widget with no matching `.tsx` would write a line that takes the site down); a new [`instrumentation.ts`](instrumentation.ts) runs `sanitizeComponentMap()` at server startup, so a dangling entry left by an interrupted run now self-heals on restart instead of keeping the site unbootable until the next generate request happens to clear it; and the build prompt now forbids deleting/renaming a component file mid-edit, since the hub recompiles on every file event and the file being absent for even the moment between a delete and the following write is enough to 500 the whole dashboard.
- **The widget-install lock is now a real lock.** The overlay shown while a new widget compiles was `position: absolute; inset: 0` against `.slot-page`, so it only ever covered that one box — and the HubCore edge dock is `right: 0` + `translateX(100%)` against `.frame-with-tabs`, which hangs it past `.frame`'s right edge and out through `.slot-page`'s padding entirely. Those protruding edge controls were the one part of the page the lock never locked, which is exactly where clicks were still landing; a monitor wider than `.slot-page`'s 1800px max-width left the gutters exposed too, and scrolling moved the page out from under it. The overlay is now `position: fixed` at `z-index: 8000` (above `.hub-core-panel`'s 200, still below `.hub-dialog-backdrop`'s 9000, preserving the previous ordering), so it covers the viewport regardless of layout, width, overflow or scroll, and `html:has(.installing-overlay)` locks scrolling behind it. Blocking is now done by `inert` on `.frame` rather than `pointer-events` — inert also stops tab-navigation into the controls underneath and removes them from the accessibility tree, where `pointer-events: none` only stopped the mouse and left everything keyboard-reachable (the old comment claimed it blocked keyboard input; it never did). The existing dim is kept as visual feedback and as a fallback where `inert` is unsupported.
- **A broken CLI sandbox no longer burns a full turn and reports success.** codex runs every command inside a bundled bubblewrap; on a host with `kernel.apparmor_restrict_unprivileged_userns=1` AppArmor denies it `net_admin`, so bwrap can't bring up loopback and *every* command — including `true` — fails before executing, while codex still exits **0**. A Widget Creator ideate run therefore spent 2m43s, wrote nothing, and surfaced as "no variation files were found on disk" as though the hub were at fault. [`limitDetection.ts`](lib/widget-creator/limitDetection.ts) now recognizes the bwrap failure signature as a third `LimitReason` (`sandbox`, alongside `quota`/`overload`) and [`harnessRunner.ts`](lib/widget-creator/harnessRunner.ts) kills the run on the first occurrence and offers the next harness in the chain — reusing the existing fallback machinery rather than adding a parallel path. Unlike the quota patterns this one is matched against content frames too, since a blocked sandbox only ever reports itself inside the harness's own command-output frames; the patterns are correspondingly narrow (each names bwrap plus its specific failure text) so generated code can't trip them. The fallback is told the previous harness wrote nothing, instead of being pointed at partial work that doesn't exist.
- **"Finished but wrote no files" now quotes the harness.** When a mockup run reports success but leaves the session dir empty, the ideate route includes the harness's own last message in the error ([`ideate/route.ts`](app/api/widget-creator/ideate/route.ts)) rather than only asserting that nothing was found — the explanation (a blocked sandbox, a refusal, a misread path) is almost always right there, and previously required scrolling the transcript to find. `runHarness`/`runHarnessChain` return the last prose chunk for this, skipping the `[tool: …]` lines every adapter normalizes to so it's the harness's reasoning and not the last file it read.
- **Widget Creator crashed on every entry card (`crypto.randomUUID is not a function`).** `crypto.randomUUID()` is a secure-context-only API, so on the hub's plain-HTTP origins (`192.168.1.24`, `*.avns.nut`) the browser leaves it undefined and `createProject` threw the moment Plan/Ideate/Build was clicked. Replaced with [`lib/uuid.ts`](lib/uuid.ts)'s `randomId()`, which builds the same v4 UUID from `crypto.getRandomValues()` (not secure-context-gated) and only falls back to `Math.random` if even that is missing. `IdeateCanvas`'s two session-id call sites had the identical latent bug and now use it too.
- **Model settings closes on a backdrop click.** Clicking the dimmed area outside the Model settings dialog now dismisses it, instead of only the `×` ([`ModelSettings.tsx`](components/widgets/default/nutbot/ModelSettings.tsx)). A native `<dialog>`'s `::backdrop` is a pseudo-element of the dialog itself, so a backdrop click reports `target === the dialog` — as does a click on the dialog's own padding, hence a bounding-rect test rather than a bare target check. Both the `pointerdown` and the `click` must land outside the box, so a drag that starts inside (selecting text, a native `<select>` popup) and releases over the backdrop doesn't dismiss the panel mid-edit. Esc already worked via `onCancel`; the model *dropdown* already closed on outside click and is unchanged.
- **Plan/Ideate/Build no longer show their idle placeholder text while generating** — an empty transcript now shows a live "thinking… / cooking up N variations… / writing the widget…" status instead of "describe a widget concept below".
- **Harness exit codes are no longer ignored.** A CLI that crashed with a nonzero exit (without tripping a rate-limit pattern) used to resolve as "done" — a crashed edit that still typechecked could be committed with zero signal. Crashes now fall forward through the harness chain with an "exited with code N" switch notice, and an exhausted chain reports an error instead of ending silently. A user pressing stop is now a distinct "aborted" outcome that never spawns the fallback harness.
- **Generated `app/api/<slug>` routes now count against the TypeScript gate.** The post-generation tsc check filtered errors to the widget component tree only, so a type-broken generated API route sailed through and 500'd at runtime.
- **Orphan pruning can no longer eat a generated-but-not-yet-installed widget.** `pruneOrphanCustomWidgetFiles` (run on every widget delete) treated any folder without a registry entry as garbage — which described exactly a widget awaiting its "install" click. Folders touched within the last 48 h are now skipped.
- **Pending Widget Creator builds survive remounts and tab closes.** Build sessions are tagged with the slug they belong to in the project record, fixing a remount bug that discarded valid resumed sessions; finished-but-uninstalled widgets also keep their install button after reload, and the orphan pruner protects synced pending-install slugs.
- **NutBot tabs stay alive while switching.** The terminal now lazy-mounts visited Log/Chat/Shells/Creator tabs and hides inactive panels instead of remounting them, so shell ptys, Widget Creator streams, and chat state survive tab switches.
- **Ideate mode aborts cleanly on unmount** and clears NutBot's working indicator, preventing orphaned ideation requests when switching stages or canvases mid-generation.
- **Plan mode replays persisted transcript history** when continuing a conversation after remount, instead of losing harness context to an in-memory history array.
- **Widget Creator handoffs are now editable and less brittle.** Plan-mode briefs live inline in the transcript with edit/build/visualize actions; finalized Ideate mockups can be built with an empty Build prompt; placement failures can reload or open Widget Manager directly; and the Build "new" action keeps the widget identity instead of wiping name/slug/edit target.
- **Widget Creator mockups and recovery flows got sharper.** Build chat now renders harness tool lines as compact chips; Ideate mode progressively reveals completed mockup files and can expand mockups into a lightbox; the creator shows a one-time focus-mode hint; and missing harness skills can be regenerated from an in-chat action.
- **Widget Creator opencode handoff is Windows-safe.** On Windows, prompt-as-argument harnesses now receive a short instruction pointing at a temporary UTF-8 prompt file, avoiding `cmd.exe` quoting problems with long freeform generation prompts.
- **Widget Creator now follows a one-way pipeline.** Plan can hand off to Ideate or directly to Build, Ideate finalizes into Build/Edit, earlier stages reopen as review-only transcripts, built widgets are labeled as Edit mode, and install refreshes return to the same project Build panel.
- **`slug`/`editSlug` are validated server-side** in the generate route before being joined into filesystem paths (previously client-side only).
- **`customComponentMap.tsx` marker comments are verified before registration** — a hand-edit that removed them used to make `addToComponentMap` silently no-op, "registering" a widget that never loads; now every registration path (generate, register, import, rename) reports an actionable error instead.
- **Deleting a custom widget from the Widget Manager now resets its creator project** back to In Progress (`syncDeletedWidget` existed but was never wired up).
- **NutBot's S/M-size status ticker no longer overlaps the face SVG's own scrolling terminal text** while a generation is in flight — the ticker now hides itself whenever the SVG is already showing that text.
- **Plan brief buttons now look visibly disabled** (dimmed, `not-allowed` cursor) instead of just being unclickable.
- **Installing a newly built widget now returns to that project's Build stage after the page reload**, instead of landing on the Projects List — the restore pointer was being cleared right after the (successful, same-tab) placement, before the Fast-Refresh reload it was meant to survive actually happened.
- **The Build-mode textbox placeholder no longer gets stuck on "hit send to build the finalized mockup"** on every later edit turn for a widget that originated from an Ideate mockup — edit mode now correctly takes priority once the widget has actually been built.
- **Plan/Ideate/Build chat transcripts no longer yank the view back to the bottom on every streamed token** if you've scrolled up to read earlier messages mid-generation (new shared [`useStickToBottom`](lib/widget-creator/useStickToBottom.ts) hook).
- **"Add to layout" no longer shows for a widget that's already on the canvas** — the button state now checks the actual placement on mount instead of always assuming unplaced.
- **Plan→Ideate handoff no longer pre-fills the prompt box with the concept text** — the carried-over brief *is* the input: the empty state says so, send works with an empty box, and the ideate API now accepts a brief-only generation (it used to reject the empty prompt server-side, which the pre-fill was masking).
- **Plan briefs now carry a master `requirements` record** — a dedicated field holding the complete spec (every user-stated field/control/behavior/state, enumerated verbatim), with the per-size content fields demoted to views that divide it up. It flows end-to-end: shown and editable in the Plan panel and Build settings, folded into Ideate's mockup prompt, Build's generation prompt, and the widget's SPEC.md — so requirements stated in Plan chat can no longer get lost between stages. The plan persona is told the brief is the only thing downstream stages ever see and must re-emit the full brief on every revision.
- **"finalize → build" (and other ideate action buttons) no longer overflow their fixed-height buttons** when the label wraps; same fix as the plan brief buttons.
- **Publishing Email widget: duplicate game IDs no longer collide** — adding a game with an existing ID is rejected (IDs key both the chip list and per-game history), and render keys tolerate already-saved duplicates.

### Removed
- The dismissible "tip: the ⤢ button…" hint from the Widget Creator workspace header.

## [2.1.0] — 2026-06-24

### Changed
- **AVN Hub now runs the Next.js dev server (`next dev`, Turbopack) as its actual runtime**, instead of a compiled `next build` / `next start` standalone image. This is required for the NutBot widget creator: generated widgets are written as real `.tsx` into the source tree and need the dev server's file-watcher/HMR to load with no rebuild, the TypeScript toolchain for validation, and the source tree + an agent CLI present at runtime. Safe because AVN Hub is single-user / self-hosted / full-trust. See [`docs/AVN_HUB.md`](docs/AVN_HUB.md) › Runtime model.
  - `Dockerfile` rewritten to a single-stage dev image that runs `npm run dev` (bound to `0.0.0.0`).
  - `docker-compose.yml` now bind-mounts the project (so agent-written widgets persist to the host and HMR sees edits) with an anonymous `node_modules` volume to avoid shadowing the image's native bindings.
  - README and `docs/AVN_HUB.md` updated with the runtime model and a recommended "run directly on the host" path (`npm run dev`) alongside the Docker path.

### Fixed
- **Per-widget error boundary hardened** ([`components/framework/WidgetShell.tsx`](components/framework/WidgetShell.tsx)). It now uses the in-palette `--status-down` token (was an undefined `--accent-red`), logs failures to the console with the widget id via `componentDidCatch`, and **resets on change** — resizing a widget, changing its settings, or an HMR module swap after an edit clears a prior error so a fixed widget recovers without a manual reload. A runtime throw in one widget still renders an inline error instead of white-screening the whole hub.
